# 属性窗口精修快照 · 2026-11-25

本轮完成第二项：歌曲（单曲、多选）、专辑、艺术家、播放列表的属性窗口。参考来源为 Windows 2.7.4 实机采集的 [06-dialogs](../../Reference-Windows-2026-11-24/capture/06-dialogs/)，不是根据 macOS 旧弹窗推测布局。日期按 Asia/Hong_Kong 记录。

[打开截图画廊](gallery.html) · [Mac 原始验收图](mac/) · [截图和源码 SHA-256](manifest.json)

| 窗口 | 本轮还原与验证 |
| --- | --- |
| 单曲 | 常规、封面图样、文件三页；分类字段、艺术家和类型可编辑下拉、均衡器、编号/总数、评分、媒体类型；上一首/下一首保留草稿 |
| 多选歌曲 | 仅常规页；标题、标题分类和歌曲/歌碟编号分子禁用；不同值显示空白；仅提交实际修改字段；没有获取歌曲信息按钮 |
| 专辑 | 常规与封面图样；专辑名称/分类、专辑艺术家/分类、类型、年份、均衡器、统计和媒体类型；保存作用于完整成员，不受搜索过滤影响 |
| 艺术家 | 常规与艺术家照片；按当前歌曲/专辑艺术家分组编辑；照片独立于歌曲封面 |
| 播放列表 | 常规与封面图样；名称/分类、统计、创建者、来源和多行注释；保存保留歌曲顺序及重复条目 |
| 共用控件 | Windows 风格的文本框、组合框、下拉列表、选中蓝色、标签下划线、按钮和箭头滚动条；640pt 面板，690/518pt 两种高度；底部按钮固定 |

属性修改在确定前为草稿。确定后保存到本地 SQLite 曲库；取消、关闭不保存。图片选择会将所选图片转换为本地 JPEG 副本，删除图片只在确认后清除本地曲库的图片引用。歌曲和专辑信息只有歌曲记录一个数据来源，避免聚合属性覆盖后来单曲修改。播放队列刷新元数据时保留队列条目，不重启播放。

文件页读取实际文件路径、格式、平均比特率（按大小/时长推导）、采样率、位深、声道和文件日期；不可读取的值显示“—”。识别服务、12 Tone Analysis 和累计传送历史没有实现。Gracenote 获取歌曲/封面信息和物理文件移动按钮说明当前支持范围。均衡器属性保存在本地，未增加按曲目自动切换音效。分类字段和媒体类型目前作为本地元数据保存，未新增基于这些字段的排序或有声读物播放引擎。未写回原音频标签、重命名或移动原文件。

## 实际执行的检查

- Release 编译通过；正式 App 与安装后的副本均通过 `codesign --verify --deep --strict`。构建仅出现不使用 AppIntents 的元数据提取提示。
- 隔离验收程序使用生产属性视图、真实 SQLite 和生成的 WAV/FLAC 测试数据，不使用用户曲库。启动 smoke 检查通过：单曲保存/重新打开、多选差异字段和明确清空、无效字段整批回滚、专辑成员修改后重新聚合、两种艺术家分组、独立艺术家图片、播放列表重复条目、属性备份恢复、无属性表的旧版 v3 备份、损坏属性备份拒绝、已删除项目拒绝保存、实际 PCM 文件事实、Vorbis 字段读取、异步加载不覆盖编辑、队列元数据刷新。修改前后测试音频 SHA-256 相同。
- 桌面实测：上一首/下一首保留草稿、取消不写入、确定后重新打开保留修改；艺术家图片从选择器读取并保存；播放列表创建者/来源保存；下拉菜单 End/Return 选择、Escape 关闭；所有属性页及长页面底部在紧凑窗口可达。设置显示颜色下拉的键盘选择和取消回归通过。
- 正式安装 App 通过歌曲、专辑、艺术家右键入口打开新属性面板。播放列表面板、字段保存与重复条目保护在隔离验收程序中验证；未创建或修改用户播放列表。
- 保存 44 张 Mac 原始截图及 5 张联系表。01–41 为隔离验收程序；42–44 为正式 App 的参考曲库入口。测试数据的歌曲时长/容量/日期与 Windows 参考资料不同，参考中的乱码分类文本没有伪造到本地曲库。

复现隔离检查：在项目根目录运行 `python3 Tests/run-properties-qa.py`，打开输出的 QA App。App 启动后运行 `Tests/PropertiesSmoke.swift`，成功显示 PASS，并提供五类属性及紧凑窗口入口。程序不自动关闭；测试曲库位于系统临时目录。构建需要可用的 Xcode/macOS SDK。
