主菜单显示 Windows 快捷键，同时保留 Mac 的 Command 导入/新建/退出入口。Ctrl+N/O/A/Shift+A、Ctrl+方向键、Ctrl+E/I、F1、F5–F10 已接至相应操作；Alt+F4 对应 Mac 的 Option+F4。菜单的可用状态来自当前曲库、选择、播放和光盘状态；缺失文件检查运行时禁用重复启动。

“搜索无文件歌曲”读取本地曲库已有文件引用，显示实际缺失数量及行标记，不扫描其他目录。权限或其他读取失败单独列为无法读取，不冒充文件缺失。F5 清除旧标记并刷新。歌曲“获取未知属性”保留 Gracenote 语义并说明服务未接入；CD 页原有 MusicBrainz 手动搜索继续保留。

删除确认默认操作和 Escape 均为“否”/“取消”。“同时删除计算机中的文件”因尚未接入而禁用，当前仍只移除曲库记录，保留原音频。真实文件移动、MP3 分类编辑器、Gracenote 业务、Windows 输出模式及设备后续状态未在本轮新增或验证。恢复、备份、ATRAC、系统信息、版本信息沿用现有处理，未把简化流程称为 Windows 完整向导。

共保存 52 张 Mac 原始截图和 6 张联系表。01–49 为隔离验收，50–52 为正式安装 App 的参考曲库入口；测试数据的时间、容量和日期不作为 Windows 固定数值。

## 实际执行的验证

- 正式 Release 编译通过；安装前后的 App 均通过 `codesign --verify --deep --strict`。构建只有未使用 AppIntents 的元数据提取提示。
- 隔离菜单 QA 使用生产 `PrototypeView`、菜单和确认框，以及独立 SQLite、生成的 WAV 和 M3U。通过：键盘跳过禁用行/分隔符、进退层级、悬停关闭旧分支、紧凑窗口边缘定位、长菜单容量、播放列表 ID 派发、实际缺失文件、重复队列身份/元数据刷新/随机排序/指定条目移除/过期菜单不移除其他条目。静音音频引擎可用，另验证了暂停时移除当前项之前的条目保持选择，移除当前项选择后继但不启动播放，最后一项移除后清空选择。
- 同一 QA 程序重新执行属性和设置回归。补强了上一轮的播放列表测试：通过 M3U 导入真正的重复条目，先断言数量及独立条目 ID，再验证属性保存、备份恢复后保留；没有把新建列表自动去重的数据当作重复条目覆盖。
- 桌面实测所有主菜单及三级选项；回车选择重复播放并关闭、再次打开显示选中状态、Escape 关闭；歌曲/专辑/艺术家/播放列表/表头/队列菜单；专辑和艺术家详情返回；表头进入列设置；黑色外观下的菜单；常规与紧凑布局、多选和列表视图。
- 桌面取消实际隔离曲库的歌曲/播放列表删除确认，没有执行删除；缺失文件检查找到预设的一个缺失文件并显示标记。队列移除数据行为在生产播放器 smoke 中验证，桌面仅展开其菜单。
- 键盘确认默认行为在直接使用生产 `WindowsDialog` 的隔离操作标记中验证，不绑定删除业务：回车选择“否”，Tab 后 Escape 仍取消。50 项生产菜单在右下角向左展开、滚动并选择末项，常规/紧凑两种尺寸通过。
- 嵌套属性验证实测：草稿标题清空后弹出错误，回车只关闭提示，仍留在属性草稿中；取消后原曲库保持 4 首、2 个列表、3 个队列条目。未改动用户曲库或删除源音频。

复现：项目根目录运行 `python3 Tests/run-menus-qa.py`，打开输出的 QA App。启动时运行菜单、属性和设置 smoke；成功后显示生产界面。工具条提供紧凑窗口、测试错误、边缘长菜单和不删除数据的确认键盘入口。测试曲库位于系统临时目录。
